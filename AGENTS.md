# Inbox+

## Code Review Rules

Treat a violation of any rule below as P1.

- The Matrix SDK is imported only in `InboxPlusMatrix`. `InboxPlusFeatures` and `InboxPlusUI` depend on
  the `MessagingGateway` protocol and never import `MatrixRustSDK`; `InboxPlusUI` never imports Sparkle.
  `InboxPlusBridge` depends on nothing beyond `InboxPlusCore`.
- Nothing unverified is executed. A bridge binary is pinned to an exact version and an upstream SHA-256,
  and its bytes are hashed and compared before it is made executable. Package dependencies stay pinned
  with `exact:`, never a version range.
- Secrets stay private: configs, registrations and cached media are `0600` inside `0700` directories, and
  the client store passphrase lives in the Keychain. Flag any log, error or diagnostic that could contain
  a token, cookie, message body or attachment URL.
- Web sign-ins use a non-persistent web view and capture only the credentials the bridge declared.
  **Open in app** follows only `https` links on a domain the named platform owns.
- Installing an update never force-kills the runtime and never discards an unsent draft, staged
  attachment or pending send. A runtime started outside the app is left running when Inbox+ quits.
- `com.inboxplus.app`, profile paths and Keychain identifiers stay unchanged between releases. A change to
  the bundled runtime contract needs a profile migration, and a failed migration never silently creates an
  empty profile.
- `Sources/InboxPlusUI/PlatformGlyphPaths.swift`, `Resources/AppIcon.icns` and `docs/sbom.cdx.json` are
  generated by the commands in `README.md`. Flag hand edits to them, and changes to their sources (brand
  icons, the logo, dependencies) that do not regenerate them.
- A test that waits on a real process needs a timeout generous enough for CI's slower macOS runners.
